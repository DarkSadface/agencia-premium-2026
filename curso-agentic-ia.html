Los mejores métodos de aprendizaje

Antes del contenido, la forma de estudiar. Este programa está diseñado sobre técnicas con respaldo en ciencia del aprendizaje. Aplícalas en cada sesión y aprenderás 2–3x más rápido.

CORE
🔨

Aprender construyendo

Project-Based Learning: cada fase produce algo funcional. No memorices APIs; constrúyelas. El proyecto es el examen.

MEMORIA
🧠

Recuerdo activo

Cierra la doc y reconstruye de memoria lo que acabas de aprender. Recordar (no releer) es lo que fija el conocimiento.

RETENCIÓN
📅

Repetición espaciada

Repasa a 1 día, 3 días, 1 semana. Crea flashcards (Anki) de comandos y conceptos clave. Vence la curva del olvido.

CLARIDAD
🗣️

Técnica Feynman

Explica cada tema en voz alta como si enseñaras a alguien. Si te trabas, ahí está tu laguna. Vuelve y repite.

ENFOQUE
🍅

Bloques Pomodoro

Sesiones de 25–50 min sin distracciones + descanso. Time-blocking en tu calendario para proteger las horas de estudio.

FEEDBACK
📈

Práctica deliberada

Repite lo que te cuesta, no lo que ya dominas. Pide a la IA que revise tu código y te dé crítica concreta.

🌀 El ciclo de cada sesión

1. Leer/ver (input) → 2. Construir (output inmediato) → 3. Explicar sin mirar → 4. Anotar dudas y comandos → 5. Repasar al día siguiente. Termina cada semana con un mini-resumen de 5 líneas: "qué aprendí, qué me costó, qué sigue".

1

Fundamentos Agentic

Claude Code · Google Antigravity · control de costos · Spec-Driven Development
Sem 1–2 ▾
Objetivo
Dominar las herramientas y la mentalidad del desarrollo agentic: usar Claude Code y Antigravity, elegir el modelo correcto (Haiku, Sonnet, Opus) controlando costos, y escribir especificaciones para que la IA construya con precisión y no por intuición.
Manual paso a paso
  1. Instala Node.js LTS y verifica con node -v. Instala Claude Code: npm install -g @anthropic-ai/claude-code y luego claude para autenticar.
  2. Crea una carpeta de práctica, abre Claude Code dentro y pídele tareas pequeñas. Observa cómo lee, planifica y edita archivos.
  3. Modelos y costos: usa Haiku para tareas simples/rápidas, Sonnet como caballo de batalla equilibrado y Opus para razonamiento complejo. Regla: empieza barato, escala solo si hace falta.
  4. Descarga e instala Google Antigravity (gratis en preview). Configura el Agent Manager y prueba los modos: agent-driven, review-driven y agent-assisted (recomendado para empezar).
  5. Spec-Driven Development: instala uv y luego Spec Kit:
    uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
  6. Inicia un proyecto y recorre el flujo: /speckit.constitution → /speckit.specify → /speckit.plan → /speckit.tasks → /speckit.implement. Revisa cada artefacto antes de avanzar.

Ejercicios prácticos
Evaluación del módulo (selección múltiple)

1. ¿Qué modelo de Claude conviene para tareas simples y de bajo costo?

Haiku es el más rápido y económico. Reserva Opus para el razonamiento más complejo.

2. ¿Qué propone el Spec-Driven Development?

La idea es que la IA construya con precisión a partir de una spec, no por intuición.

3. ¿Qué es Google Antigravity?

Antigravity es una plataforma agéntica donde los agentes planifican, ejecutan y verifican tareas.

4. Regla recomendada para controlar costos:

Empieza barato (Haiku/Sonnet) y sube a Opus únicamente cuando la tarea lo exige.

5. El orden típico del flujo en Spec Kit es:

Primero la constitución (reglas), luego la spec, el plan, las tareas y por último implementar.

Desarrollo de App Real

Next.js · Supabase · Tailwind · shadcn/ui · Claude Vision
Sem 3–4 ▾
Objetivo
Convertir wireframes en interfaces funcionales y conectar datos reales. Pasar de una maqueta a una aplicación que autentica usuarios y guarda información.
Manual paso a paso
  1. Crea el proyecto base: 
    npx create-next-app@latest mi-app
    elige App Router y TypeScript.
  2. Configura Tailwind (ya viene integrado) e instala shadcn/ui: npx shadcn@latest init y agrega componentes con npx shadcn@latest add button card input.
  3. Claude Vision: sube una captura o wireframe a Claude y pídele que genere los componentes React/Tailwind correspondientes. Itera sobre el resultado.
  4. Crea un proyecto en Supabase, define tablas en el editor SQL y configura autenticación (email/OAuth).
  5. Conecta la app con las claves del proyecto Supabase y reemplaza datos mock por datos reales (consultas con el cliente @supabase/supabase-js).
  6. Protege rutas y muestra contenido según el usuario autenticado. Verifica el ciclo completo: registro → login → datos propios.

RAG & Chatbot Contextual

RAG · embeddings · pgvector · información privada
Sem 5–6 ▾
Objetivo
Integrar RAG, embeddings y pgvector para crear un chatbot contextual que responde usando información privada del producto, no solo conocimiento general del modelo.
Cómo funciona un RAG (gráfica)
Manual paso a paso
  1. En Supabase, habilita la extensión vector (Database → Extensions → buscar "vector").
  2. Crea la tabla de documentos con una columna de embedding: 
    create table documents (
  id uuid primary key default gen_random_uuid(),
  content text,
  embedding vector(1536)
);
  3. Chunking: divide tus documentos en fragmentos pequeños (p. ej. 500–800 tokens) para mejorar la recuperación.
  4. Genera embeddings de cada chunk (con un modelo de embeddings) y guárdalos en la tabla.
  5. Crea un índice HNSW para búsqueda por coseno: 
    create index on documents using hnsw (embedding vector_cosine_ops);
  6. Pipeline RAG: ante una pregunta → genera su embedding → recupera los chunks más similares (<=>) → arma el prompt con ese contexto → genera la respuesta citando fuentes.

Checklist de la fase
Ejercicios prácticos
Evaluación del módulo (selección múltiple)

1. ¿Qué significa RAG?

RAG recupera información relevante y la usa como contexto para generar la respuesta.

2. ¿Qué guarda un "embedding"?

El embedding es un vector que captura el significado, permitiendo comparar por similitud.

3. pgvector se usa para…

Es la extensión de Postgres (Supabase) que habilita la búsqueda vectorial.

4. ¿Por qué se hace "chunking" de los documentos?

Fragmentos más pequeños permiten recuperar justo la parte relevante a la pregunta.

5. Ante una pregunta, un RAG primero…

Recuperar → aumentar el prompt con ese contexto → generar la respuesta con fuentes.

Agentes Avanzados & Testing

MCP · Custom Skills · Vitest · Playwright E2E
Sem 7–8 ▾
Objetivo
Conectar agentes a herramientas externas con MCP, crear Custom Skills reutilizables y respaldar todo con pruebas: tus agentes generan, validan, corrigen y mejoran el código con Vitest (unitarias) y Playwright (E2E).
La pirámide de testing (gráfica)
Manual paso a paso
  1. MCP (Model Context Protocol): entiende qué es —un estándar para que los modelos usen herramientas y datos externos— y conecta un servidor MCP a Claude.
  2. Crea una Custom Skill: una carpeta con instrucciones y recursos que el agente carga cuando son relevantes. Empaqueta una tarea recurrente tuya como Skill.
  3. Vitest: instala npm i -D vitest y escribe pruebas unitarias de tu lógica y funciones puras. Apunta a feedback en < 2 s.
  4. Playwright: npm init playwright@latest. Escribe E2E de los flujos críticos (login, checkout, búsqueda) que cuestan dinero si fallan.
  5. Aplica el reparto 70/20/10: muchas unitarias, algunas de integración, pocas E2E. Usa npx playwright codegen para generar pruebas rápido.
  6. Pide a tu agente que ejecute las pruebas, lea los fallos y se autocorrija hasta dejar todo en verde.

Ejercicios prácticos
Evaluación del módulo (selección múltiple)

1. ¿Qué es MCP (Model Context Protocol)?

MCP estandariza cómo un modelo accede a herramientas, archivos y servicios externos.

2. Vitest se usa principalmente para…

Vitest corre pruebas unitarias muy rápido, ideal para lógica y funciones puras.

3. Playwright sirve para…

Playwright automatiza el navegador para validar flujos completos como un usuario real.

4. Según el reparto 70/20/10, ¿qué pruebas deben ser mayoría?

~70% unitarias (rápidas), 20% integración y solo ~10% E2E (lentas pero realistas).

5. Una Custom Skill es…

Las Skills encapsulan know-how que el agente carga cuando es relevante para la tarea.

Producción & Optimización

GitHub Actions · CI/CD · Vercel · performance · docs automática
Sem 9–10 ▾
Objetivo
Llevar la app a producción con calidad automatizada: pipeline de CI/CD con GitHub Actions, despliegue en Vercel, optimización de performance y documentación automática.
El pipeline CI/CD (gráfica)
Manual paso a paso
  1. Sube el proyecto a un repo de GitHub. Asegura que npm run lint, test y build pasan en local.
  2. Crea un workflow en .github/workflows/ci.yml que corra lint → tests → build en cada push y PR.
  3. Conecta el repo a Vercel. Cada push genera un preview deploy; main despliega a producción automáticamente.
  4. Configura las variables de entorno (claves Supabase, etc.) en Vercel, separando preview de producción.
  5. Performance: mide con Lighthouse / Core Web Vitals y optimiza imágenes, fuentes y carga (lazy loading, caching).
  6. Documentación automática: pide al agente que genere y mantenga el README, changelog y docs técnicas a partir del código.

1. ¿Qué hace un pipeline de CI/CD?

CI/CD integra y entrega de forma continua: cada push pasa por controles automáticos.

2. GitHub Actions se configura con archivos…

Los workflows son archivos .yml que definen los jobs y cuándo se ejecutan.

3. Vercel se usa para…

5. Un "preview deploy" es…

Permite revisar cada cambio en una URL propia antes de fusionar a producción.
